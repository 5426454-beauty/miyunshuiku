第1幕：开场定调（1.5分钟）
─────────────────────────

【演讲词】
各位领导/专家好，今天我为各位演示的是——
"密云水库数字孪生智能防汛推演系统"。

接下来15分钟，我们不按功能模块逐一介绍，而是完整走一遍
"暴雨洪水应急响应"的真实业务流程——从气象预警、灾前评估、
应急决策、联动执行，到效果验证，一个完整的闭环。

这个闭环中，AI 扮演三个角色：
第一，"眼睛"——大模型视觉能力实时分析2D卫星图和3D场景；
第二，"大脑"——DEM淹没模型精确计算每一格点的水深；
第三，"手"——自然语言交互一键操控场景中的闸门、降雨、无人机。

一句话概括：让 AI 不仅"看懂"数字孪生场景，更能"算准"洪水风险。

【演示操作】
- 打开系统首页，展示3D场景+左右面板
- 快速过一眼整体界面（不做细讲，5秒）


第2幕：暴雨预警触发（1.5分钟）
─────────────────────────────

【演讲词】
好，故事从这里开始。

现在是汛期。气象台刚刚发布了暴雨黄色预警——
预计未来24小时，密云水库流域累计降雨量将达到120毫米。

如果是传统方式，预警信息只是一条短信、一个电话。
但在我们的系统里，只需要对AI说一句话。

【演示操作】

▶ 语音或文字输入：
  "收到暴雨预警，未来24小时密云水库流域降雨120毫米，启动应急响应"

  → AI 流式输出响应，同时自动执行：
    ⚡ 切换天气为暴雨（ModerateRain）
    🕐 设置时间线到上午8:00
    📷 相机飞到水库全景最佳观察视角
    💬 AI给出初步应急提示："正在为您进行灾前风险评估……"

【演讲词】
大家注意，190个字的一次语音输入，AI同时完成了三个动作——
天气切换、时间设定、相机飞行。
并且它已经开始思考下一步该做什么。

接下来我们进入最关键的一步：灾前评估。


第3幕：灾前评估——AI 看图、算数、做研判（3.5分钟）⭐
─────────────────────────────────────────────────

【演讲词】
防汛的核心问题是三个：
  哪些地方会被淹？
  水会涨到多深？
  哪些设施和建筑面临风险？

要回答这些问题，需要三件事：
  第一，DEM高程分析——找到低洼区域；
  第二，AI图像识别——找出区域内的建筑和道路；
  第三，淹没水深计算——120mm降雨下，每一栋建筑的预估水深。

我们的系统恰好把这三件事串在了一起。

【演示操作】

▶ 第一步：DEM 高程分析（30秒）
  AI 对话输入：
  "分析库区周边海拔低于150米的低洼区域，并统计面积"

  → 后端自动调用 query_elevation.py
    (基于 9422×17767 分辨率 DEM TIF，scipy.ndimage.label 连通区域分析)
  → 返回 2 个低洼连通区域（走马庄副坝下游 + 潮河主坝下游）
  → POI 标记 + 矩形框标注到 3D 场景
  → AI 播报："发现2个低洼区域，总面积XX平方公里"

【演讲词（分析进行中）】
这是第一步——利用 DEM 高程数据，用 scipy 连通区域算法，
自动识别出所有海拔低于 150 米的低洼地带并标注到场景中。

但知道"哪里低"只是开始。我们还要知道"低洼处有什么"。


▶ 第二步：2D 卫星图 AI 识别 + 淹没水深计算（1.5分钟）

  切换至 2D 卫星图，飞到低洼区域上空。

  AI 输入：
  "统计低洼区域内的建筑数量，测量区域内的道路总长度，
   并基于120mm降雨计算每栋建筑的预估淹没水深"

  → 系统自动：
    ① 📷 截取卫星图 → Qwen3.7-Plus 视觉模型识别 → 红框标注每栋建筑
       → 统计：共 23 栋建筑
    ② 📏 AI 测量道路中心线 → Haversine 折线算距 → 道路总长 3.2 公里
    ③ 🌊 调用淹没水深计算系统（预计算的 120mm/24h 格点数据）
       → 将每栋建筑的坐标映射到格点
       → 输出逐栋水深：

        建筑A1（走马庄下游） → 最大水深 1.8m ⚠️
        建筑A2                 → 最大水深 1.2m ⚠️
        建筑B3                 → 最大水深 0.3m
        建筑C5（潮河下游）      → 最大水深 0.8m ⚠️
        ……（共 23 栋）

    ④ 2D 标注结果自动同步到 3D 场景

【演讲词（分析进行中）】
大家注意，这一步是关键转折点。

如果是传统数字孪生，到这里只是"AI 看到了 23 栋建筑"——定性判断。
但我们用淹没水深计算系统预先生成了完整格点数据，
AI 把每栋建筑的坐标映射到格点上，查出了精确的水深值。

结果出来之后，23栋建筑被分成了两类：
15栋位于高风险区，预估水深超过0.5米；
8栋位于相对安全区，水深不足0.3米。

这不是看图猜出来的，是算出来的。


▶ 第三步：3D 场景 AI 检测——设施完好性检查（1分钟）

  切回 3D 视图，AI 输入：
  "检查第三溢洪道和泄洪设施是否完好"

  → 相机飞向溢洪道
  → 截取 3D 视频帧 → Qwen Vision 分析
  → 返回："溢洪道结构完整，6个闸门均可正常启闭，泄洪设施状态良好"
  → 在 3D 场景标注检测到的设施

【演讲词】
AI 不光看 2D 卫星图，还能直接分析 3D 场景。
截取当前的数字孪生画面，告诉模型这段溢洪道看起来是否完好。

这一步的意义是——在真正开闸泄洪之前，
AI 已经替我们确认了设施的可用性。


▶ 第四步：AI 综合输出风险画像（30秒）

  AI 将所有分析结果汇总：
  ┌─────────────────────────────────────────┐
  │ 📊 120mm暴雨风险画像                      │
  │                                          │
  │ 🌊 低洼区域：2处，总面积 XX km²            │
  │ 🏠 受影响建筑：15栋（最大水深1.8m）         │
  │ 🛣 受影响道路：3.2公里                     │
  │ 🏗 泄洪设施：3处，状态完好                  │
  │                                          │
  │ ⚠️ 建议：提前开闸预泄 + 启动淹没预演        │
  └─────────────────────────────────────────┘

【演讲词】
三步分析在1分半钟内全部完成。
这不是"AI秀功能"，而是实打实的灾前风险评估——
每一栋建筑的水深、每一段道路的长度、每一个设施的完好性，
都有数据支撑。


第4幕：应急决策——AI 辅助调度（1.5分钟）
───────────────────────────────────────

【演讲词】
风险评估做完了，接下来是决策。

AI 的建议很明确：提前开闸预泄降低库容，同时启动50年一遇洪水预演，
验证最坏情况下的淹没范围。

我们要做的，就是确认执行。

【演示操作】

▶ AI 对话输入："确认，开始执行"

  AI 输出调度方案：
  ┌──────────────────────────────────────┐
  │ 📋 应急调度方案                        │
  │                                       │
  │ ① 降雨模拟：120mm/24h，中间峰值型雨型  │
  │ ② 淹没预演：50年一遇，4阶段演进        │
  │ ③ 闸门调度：03/04号闸门 50%开度预泄    │
  │ ④ 持续监测：每小时更新淹没范围和水深   │
  │                                       │
  │ ⏱ 预计执行时间：约1分钟（压缩演示）      │
  └──────────────────────────────────────┘

【演讲词】
大家注意一个细节：在这段对话过程中，AI助手没有"凭空说话"。
它的所有建议都基于第3幕产出的数据——D E M、图像识别、淹没水深计算。
这就是"AI赋能决策"和"AI聊天机器人"的本质区别。


第5幕：联动执行——淹没预演+闸门调度（3.5分钟）⭐
──────────────────────────────────────────────

【演讲词】
好，现在进入最直观的阶段——洪水来了。

但与传统的"水面均匀抬升"不同，我们要展示的是一张
基于DEM格点计算的、非均匀的淹没水深时序热力图。

【演示操作】

▶ 阶段指示器显示在场景左上角（半透明步骤条）

  ①【降雨积蓄】T+0 ~ T+6h（约45秒）

    降雨模拟启动：AI 切换到暴雨天气 + 调用淹没水深时序数据
    2D 地图上渲染格点水深热力图：
      - 低洼处首先出现蓝色→青色点（水深0~0.3m）
      - 高处和坝体上方保持绿色（水深0m）
      - 5倍速播放 T+0 到 T+6h

    演讲（同步）：
    "大家看，这不是均匀的蓝色一片，而是低洼处先积水，
     高处不受影响。每一个彩色格点都有自己的水深数值——
     来自DEM模型算出来的结果，不是视觉特效。"


  ②【水位上涨】T+6 ~ T+12h（约45秒）

    热力图颜色加深：
      - 走马庄副坝下游大面积变黄→橙（水深0.5~1.2m）
      - 建筑标注变色：绿色→黄色→橙色（逐栋显示水深变化）
      - 水面 WaterSurface API 联动抬升至 155m

    演讲（同步）：
    "到第12小时，累计降雨量达到峰值。
     走马庄副坝下游15栋建筑中，已经有8栋进入橙色预警区，
     水深超过0.5米。"
    "但注意，坝体上方仍然是绿色——因为地形高，水淹不到。"


  ③【低洼漫溢】T+12 ~ T+18h（约30秒）

    热力图继续扩散：
      - 潮河主坝下游区域开始积水
      - 道路标注变色：蓝色→橙色（水深0.1→0.8m）
      - 3D 场景同步更新 POI 标注颜色

    闸门调度启动：
      → AI 自动执行：03号闸门开度50%，04号闸门开度50%
      → 水花特效出现
      → 闸门面板显示实时开度

    演讲（同步）：
    "到18小时，降雨虽然开始减弱，但径流累积仍在上涨。
     系统按照预设计划，自动开启03号和04号闸门进行预泄——"


  ④【淹没峰值+全力泄洪】T+18 ~ T+24h（约45秒）

    淹没达到峰值：
      - 最深格点水深 1.8m（走马庄下游）
      - 受影响建筑 15 栋全数进入红色区域
      - 3D 场景俯瞰——整个低洼区被淹没

    全力泄洪：
      → AI 自动开启 01~06 全 6 个闸门
      → 每个闸门分级开启（0.3→0.5→0.7→1.0）
      → 水花从闸口倾泻而出

    演讲（同步）：
    "第24小时，淹没达到峰值——15栋建筑全部面临威胁。
     此时系统自动触发全闸门泄洪——"

  【阶段指示器消失，表示联动执行完成】

    演讲：
    "20秒内走了4个阶段24小时——但每一帧的水深数据都来自真实计算。
     这就是DEM 淹 没 模 型 和简单水面抬升的本质区别：
     不是说'水涨了多少米'，而是说'每一个格点、每一栋建筑、
     水涨了多少'。"


第6幕：效果验证——AI 前后对比（2分钟）⭐
─────────────────────────────────────

【演讲词】
演完了不叫结束。
防汛调度到底有没有效果？AI 来告诉我们答案。

【演示操作】

▶ 泄洪前后对比分析

  AI 对话输入：
  "对比泄洪调度前后的淹没情况，评估调度效果"

  → 系统自动：
    ① 读取淹没前（T+24h峰值）的格点水深数据
    ② 读取泄洪后（T+48h退水）的格点水深数据
    ③ 逐格点做差：Δ = 泄洪后水深 - 峰值水深

  → AI 输出量化对比报告：
    ┌──────────────────────────────────────────┐
    │ 📊 泄洪调度效果评估                        │
    │                                           │
    │ 🏠 受影响建筑：15栋 → 5栋（减少67%）        │
    │ 📏 受影响道路：3.2km → 0.8km（减少75%）     │
    │ 🌊 最大水深：   1.8m → 0.4m（降低78%）      │
    │ 📐 淹没面积：    XX km² → XX km²            │
    │                                           │
    │ ✅ 结论：泄洪调度有效降低了淹没风险，        │
    │    但建议对走马庄下游5栋建筑提前人员转移。   │
    └──────────────────────────────────────────┘

【演讲词】
从15栋减少到5栋，最大水深从1.8米降到0.4米——
每一个数字都不是估算，而是从 DEM 格点数据里算出来的。

更重要的是，AI 还给出了后续建议——
提醒我们走马庄下游那5栋建筑仍然有风险，可能还需要人员转移。

大家注意到没有：整个闭环在这里真正"闭合"了。
预警 → 评估 → 决策 → 执行 → 验证，
而 AI 贯穿了每一个环节，每一步都有数据支撑。

【需要提前准备的数据（路演前一天完成）】

  ★ 淹没水深预计算（关键项）
    1. 准备密云水库边界文件（KML/GeoJSON，从现有点位构造或手工绘制）
    2. 将"高程5米.tif"和边界文件放入 淹没水深计算系统V2.0\data\input\
    3. 运行 EXE，设置参数：
       - DEM文件：高程5米.tif
       - 边界文件：密云水库边界
       - 降雨模式：自定义降雨
       - 总降雨量：120mm
       - 降雨历时：24小时（中间峰值型）
       - 模拟时长：48小时（含24h退水期）
       - 网格步长：5~10（平衡精度和计算时间）
    4. 将输出结果：
       - GridIDArray*.json / ValueArray*.json → 拷贝到项目 data/flood/ 目录
       - flood_map.html → 可用于 iframe 嵌入
       - flood_depth.shp → 可用于 3D 场景渲染

    备选方案：如果 EXE 计算时间太长（网格过密），可用大步长(20)做快速预览版

【需提前打开的页面】
